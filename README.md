# 네이버 가계부 자산화 프로젝트 “Grimault”

# 진행 배경

- 네이버에서 주력으로 관리되는 제품이 아닌 바, 운영 지속에 대한 불확실성 우려
- 기초적인 편의성에 대한 갈증: 사용 내역 전체 탐색, 모바일 UI 미제공 등
- 2012년부터 작성해 온, 삶의 궤적이라고 볼 수도 있는 중요 자료에 대한 자산화 필요성 인지

# 목표

> [!IMPORTANT]
> **“네이버 가계부를 완전히 대체할 수 있는 가계부를 완성한다”**

## 주요 목표

- 2012년부터 2026년 작업 완료 시기까지 총 14년 간의 데이터를 성공적으로 개인 자산화
- 원본 데이터를 기반으로 추가 작성의 연속성을 보장할 수 있는 인터페이스 개발
- 네이버 가계부 내 주요 활용 기능을 비롯해 검색과 모바일 환경 등 일부 기초적 불편 사항 개선

## 부수적 목표

- 퇴직(2025년 6월) 이후 장기간 떨어진 개발 감각에 대한 리듬감 회복
- 향후 즉각적인 배포와 업데이트 반영을 위한 홈랩 아키텍처 구성

## 완료 기준

- 가계부 전용 데이터베이스 구축: 전체 탐색을 고려한 인덱스 최적화
- 가계부 작성 인터페이스 완성: 웹과 모바일 모두

## 목표로 삼지 않아야 하는 것

- 편의 기능 고도화: 소비 패턴 등에 대한 시각화 대시보드 작성 등 (초도 개발 완료 후 고려)
- 수려한 디자인: UI보다는 UX에 치중하되, 통상적인 UX 수준에서 완성 (익숙한 맛)

# 의존성

- [홈랩 아키텍처 구성](docs/homelab-architecture-roadmap.md) (메인 프로젝트와 별도로 수행)
- 백엔드 기술 스택은 Kotlin/Spring으로 부수 목표 방향성 유지

# 부작용과 위험 요소

## NAS 홈랩 구축에 따른 리스크 우려

- 홈랩 구축을 동시에 진행하는 것은 주요 프로젝트의 목적과 부합하지 않음
- 인프라 단에서 발생 가능한 예상할 수 없는 트러블슈팅으로 리소스 소모 우려
- **대안 → NAS 홈랩 구성은 가계부 기능 동작을 우선 완료한 후에 분리해서 별도 진행**

## 원본 데이터 가용성 점검

- 네이버 가계부에서 내보내기를 통해 내려받은 데이터 정확도에 대한 불확실성
- 카테고리 및 결제 수단(계정) 등 관계형 매핑 데이터 스키마 분리 시점 결정 필수

## 프론트엔드 기술 스택 러닝커브

- 아무리 수월한 기술 스택을 선정하더라도 직접 개발에 드는 공수 예측 불가
- 필요 시 AI에게 완전히 넘겨서 작업하는 방향도 고려할 필요 (결과물 퀄리티 보장 가능?)
