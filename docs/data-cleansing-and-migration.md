# 데이터 클렌징 및 마이그레이션 실행 전략

## 1단계: 마스터 데이터 시드 적재
### 1. 금융 계정 `public.account` 등록
- 전체 지출/수입 이력에서 등장한 고유 계정 31개를 추출 및 적재 (`raw.outgo`, `raw.income`)
- 현재 실사용 중인 계정에 `is_active = true`, 나머지는 `is_active = false`
- 각 계정별 자산 유형 (`type`, `sub_type`) 및 (신용카드) 결제일 (`settlement_day`) 매핑

### 2. 분류 카테고리 `public.category` 등록
- 원본 데이터 상 2단계 분류 전체를 고유 값으로 추출 및 적재 (`parent_name`, `sub_name`)
- 단, 네이버 가계부에서 분류로 다루는 '이체/대체', '카드대금'의 경우 복식부기 분개 대상이므로 제외
- 원본 내 일회성으로 등장한 일부 카테고리는 대표 카테고리로 통합 (데이터 점검 간 3건 발견)
- 각 대분류의 '기타' 항목 매핑 항목 752건은 기록 보존을 위해 그대로 유지

## 2단계: 거래 헤더 `public.transaction` 및 분개 원장 `public.ledger_entry` 마이그레이션
### 3. 일반 소비 지출 및 단순 수입 (전체 데이터의 약 90%)
- 원본 내 현금/카드 동시 결제 건 0건이므로 일반 지출 및 수입은 1:1 분개로 대응 가능
- 지출: 자산/부채 계정 감소(-) 1건 + 비용 `EXPENSE` 카테고리 인식(+) 1건
- 수입: 자산 계정 증가(+) 1건 + 수익 `REVENUE` 카테고리 인식(-) 1건

### 4. 계정 간 이체 및 대체 변환
- 원본 데이터 상 '이체/대체' 대분류에 속한 지출 데이터를 **자산 간 이동 거래**로 변환
- 출금 계정 자산 감소(-) 1건 + 대상 계정 자산 증가(+) 1건으로 분개 `category_id is null`

### 5. 신용카드 대금 상환 변환
- 원본 데이터 상 '카드대금' 대분류에 속한 지출 데이터를 **부채 청산 거래**로 변환
- 출금 통장 자산 감소(-) 1건 + 신용카드 부채 감소/청산(+) 1건으로 분개 (손익 왜곡 차단)

### 6. 선불 충전 교정 (약 150여 건)
- 현금 충전: 출금 통장 자산 감소(-) 1건 + 대상 선불 자산 증가(+) 1건으로 분개 (예: 쿠팡, 네이버 등)
- 카드 충전: 신용카드 부채 증가(-) 1건 + 선불 자산 증가(+) 1건으로 분개 (예: 스타벅스, 미용실 등)

## 3단계: 무결성 검증 및 밸런스 점검
### 7. Zero-Sum 불변식 검증
- 전체 분개 합계가 정확히 `0.00`인지 검증
  ```sql
  SELECT sum(amount) FROM public.ledger_entry;
  ```

### 8. 계정 단위 잔액 대조
- 각 계정별 최종 잔액이 원본 데이터 총 잔액과 일치하는지 대조
  ```sql
  SELECT sum(amount) FROM public.ledger_entry WHERE account_id = {id};
  ```
