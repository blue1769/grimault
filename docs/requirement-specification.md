# Grimault v1 기능 요구 스펙 정의서 (Requirements Specification)

## 1. 개요 및 설계 원칙

본 문서는 네이버 가계부의 14년 치 아카이브 데이터 자산화 및 독립 가계부 구축 프로젝트인 **Grimault**의 v1 핵심 기능 요구사항을 정의한다.

* **최소주의 실용주의 (Radical Minimalism)**: 네이버 가계부에 존재하던 기능 중 14년간 실제로 사용하지 않은 기능(예산, 소셜 피드, 복합 차트 등)은 철저히 배제하고, 실제 손에 익은 핵심 인터랙션만 구현한다.
* **복식부기 불변식 준수 (Zero-Sum Invariant)**: 모든 거래는 다중 분개 원장(`ledger_entry`)을 통해 오염률 0%의 회계 무결성을 유지한다.
* **키보드 중심 입력 (Keyboard-First UX)**: 마우스 클릭 강제를 지양하고 날짜, 금액, 사용처 등의 연속 입력을 보장한다.
* **기간 족쇄 없는 전역 검색 (Unbounded Search)**: 과거 14년 치 전체 데이터를 대상으로 10ms 이내에 즉시 낚아 올리는 고속 탐색 환경을 제공한다.

## 2. 도메인 코어 및 계정 체계

### 2.1 계정(Account) 마스터 및 자산 분류
복잡한 금융권식 자산 분류를 지양하고, 실생활 유동성에 기반한 4대 계정 성격(`sub_type`)으로 단순화한다.

| 계정 유형 (`type`) | 세부 성격 (`sub_type`) | 설명 및 실사용 매핑 |
| :--- | :--- | :--- |
| **ASSET** (자산) | `BANK` | 은행 입출금 통장 (구 급여통장, 생활비통장 등) |
| | `CASH` | 실물 현금 및 지갑 잔액 |
| | `PREPAID` | 선불 충전 머니 (네이버머니, 스타벅스 App 등 잔액 보유체) |
| **LIABILITY** (부채) | `CREDIT_CARD` | 신용카드 사용 잔액 (카드 대금 청구 대상) |

* **체크카드 처리 정책**: 체크카드는 독자 계정으로 생성하지 않으며, 연결된 은행 계좌(`BANK`)를 원장 주체로 삼고 거래 헤더의 `payment_method` 속성으로 분리 관리한다.
* **신용카드 결제일 메타데이터**: `account` 테이블에 `settlement_day`(1~31)를 보관하며, 이용 기간(전표 매입 구간)은 백엔드 도메인 서비스의 카드사별 정적 룰 엔진에 의해 동적으로 산정한다.
* **상태 관리**: 현재 유효한 6개 계정만 활성화(`is_active = true`)하여 작성 UI에 노출하고, 과거 25개 계정은 보존 조회용(`is_active = false`)으로 격리한다.

## 3. 핵심 기능 요구사항 (Core Features)

### 3.1 거래 기록 인터페이스 (Entry Flow)
네이버 가계부의 익숙한 스프레드시트형 인라인 입력 UX를 계승한다.

* **화면 초기 상태**: 앱 진입 시 지출 폼이 기본 포커스되며, `transaction_date`는 당일(`LocalDate.now()`)로 자동 바인딩된다.
* **날짜 수기 입력 보장**: 달력 팝업 강제를 제거하고, `YYYY-MM-DD` 및 `MMDD` 형태의 키보드 직접 타이핑을 최우선 지원한다.
* **필수 필드 분리 보장**: 사용처(`merchant`)와 상세내역(`description`)을 독립 필드로 유지하여 14년간 축적된 입력 리듬을 보존한다.
* **태그 및 낭비 플래그**:
    * `tags`: 검색 닻(Search Anchor) 목적의 경량 텍스트 유지.
    * `is_waste`: 불필요한 지출 반성을 위한 단순 토글 플래그 유지.
* **복식부기 자동 분개 처리**:
    * **단순 지출**: 출금 계정 차감(-) + 비용 카테고리 매핑(+)
    * **계좌 간 이체/충전**: 출금 계정 차감(-) + 입금 계정 증액(+) (지출 0원)
    * **카드 충전식 선불 자산**: 카드 부채 증가(-) + 선불 계정 증액(+) (가짜 수입/지출 원천 차단)

### 3.2 고속 전역 검색 및 탐색 (Search Engine)
네이버 가계부의 부실한 형태소 분석과 기간 강제 필터를 완전히 대체한다.

* **기간 제약 없는 전역 스캔**: 시작일/종료일 조건이 없을 경우 전체 14년 치 원장을 기본 스캔 대상으로 삼는다.
* **다중 컬럼 통합 매칭**: 단일 검색어 입력 시 `merchant`, `description`, `tags`, `category`를 일괄 검사한다.
* **정확도 보장 (AND Tokenizing)**: 공백으로 구분된 다중 키워드(예: `RTX 5070`)에 대해 대소문자 무시(ILIKE) `AND` 조건으로 완전 매칭을 보장한다.
* **선택적 조건 필터**: 특정 연월 구간(`startDate` ~ `endDate`), 수입/지출/이체 구분(`entry_type`), 계정 식별자(`account_id`)를 통한 좁혀보기 쿼리를 지원한다.

### 3.3 단일 뷰 스탠다드 대시보드 (Integrated Summary)
네이버 가계부의 4개 탭(월보고서, 연간보고서, 지출분석, 자산현황)을 넓은 화면 낭비 없이 1개의 컴팩트 뷰로 통폐합한다.

* **당월 손익 요약**: 총수입, 총지출, 수입 대비 지출 소진율 게이지바 제공.
* **카테고리 지출 현황**: 페이지 이동 없이 대분류 랭킹 및 하위 소분류 지출 상세를 인라인으로 확장 표시.
* **자산/부채 실시간 요약**: `순자산 = 자산 총계 - 부채 총계` 공식에 따른 4대 `sub_type`별 합계 요약.
* **낭비 지출 요약**: 당월 낭비 지출(`is_waste = true`)의 총액 및 건수 표시.
* **연간 월별 트렌드**: 최근 6~12개월간의 수입/지출 추이 미니 매트릭스 제공.

## 4. 백엔드 API 명세 (Draft)

### 4.1 거래 관리 (Transactions)
* `POST /transactions`: 거래 등록 (지출, 수입, 이체 분개 생성)
* `PUT /transactions/{id}`: 거래 수정 (헤더 및 연관 분개 갱신)
* `DELETE /transactions/{id}`: 거래 삭제 (CASCADE 분개 제거)
* `GET /transactions`: 당월 거래 목록 조회 (페이징/정렬)

### 4.2 전역 검색 (Search)
* `GET /search`: 전역 다중 키워드 및 조건부 고속 검색
    * Query Params: `keyword`, `startDate`, `endDate`, `entryType`, `accountId`

### 4.3 통합 통계 및 요약 (Dashboard & Reports)
* `GET /reports/monthly`: 특정 연월 손익, 카테고리(대/소) 랭킹, 낭비 지출 집계
* `GET /reports/annual-trend`: 지정 연도 1~12월 수입/지출 매트릭스
* `GET /accounts/summary`: 실시간 계정별 잔액 및 순자산 요약
* `GET /accounts/{id}/billing-estimate`: 신용카드 결제일 기준 출금 예정액 조회

### 4.4 마스터 데이터 (Master Data)
* `GET /categories`: 활성 카테고리 목록 트리 조회
* `GET /accounts`: 활성 계정 목록 조회 (`is_active = true`)
