# 신규 거래 등록 시 원장 시작일 검증 (Transaction Date Validation)

## 개요

신규 일반 거래의 거래일은 참여하는 모든 금융 계정의
원장 시작일(openingDate) 이상이어야 한다.

원장 시작일 당일의 거래를 허용하며,
현재 날짜를 기준으로 별도의 미래 거래일 제한을 두지 않는다.

## 테스트 대상

- `TransactionService.create()`

## 테스트 시나리오

### 1. 원장 시작일 당일 및 미래 날짜의 거래를 허용한다

- **대상:** `TransactionService.create()`
- **시나리오:** 거래일이 참여 금융 계정의 원장 시작일 이상이라면
  원장 시작일 당일 및 미래 날짜의 거래도 정상적으로 등록한다.
- **사전 조건:**
    - SPENDING 요청을 구성한다.
    - 참조 금융 계정과 손익 분류는 유효하다.
    - Repository는 Mock으로 구성한다.
    - 거래 저장 시 식별자가 부여된 거래를 반환하도록 구성한다.
- **실행:** `create(request)` 호출
- **기대 결과:**
    - `TransactionRepository.save()`가 한 번 호출된다.
    - 저장 대상 거래의 거래일이 요청 거래일과 일치한다.
    - 응답의 거래일이 요청 거래일과 일치한다.
- **테스트 형태:** `@ParameterizedTest`

#### 입력 조건

| 금융 계정 원장 시작일 | 거래일 | 기대 결과 |
|---|---|---|
| 현재 날짜 | 원장 시작일 당일 | 정상 등록 |
| 현재 날짜 | 현재 날짜의 다음 날 | 정상 등록 |

### 2. 금융 계정의 원장 시작일 이전 거래를 거부한다

- **대상:** `TransactionService.create()`
- **시나리오:** 단일 금융 계정이 참여하는 거래의 거래일이
  원장 시작일 이전이면 거래 등록에 실패한다.
- **사전 조건:**
    - SPENDING 요청을 구성한다.
    - 참조 금융 계정과 손익 분류는 유효하다.
    - 금융 계정의 원장 시작일은 2026-01-01이다.
    - 거래일은 2025-12-31이다.
    - Repository는 Mock으로 구성한다.
- **실행:** `create(request)` 호출
- **기대 결과:**
    - `INVALID_TRANSACTION_ACCOUNT`에 해당하는
      `GrimaultException`이 발생한다.
    - `TransactionRepository.save()`는 호출되지 않는다.
- **테스트 형태:** `@Test`

### 3. 이체 거래의 모든 참여 계정에 대해 원장 시작일을 검증한다

- **대상:** `TransactionService.create()`
- **시나리오:** 이체 거래에 참여하는 두 금융 계정 중 하나라도
  거래일이 원장 시작일 이전이면 거래 등록에 실패한다.
- **사전 조건:**
    - TRANSFER 요청을 구성한다.
    - 원계정과 목적계정은 서로 다른 활성 BANK 계정이다.
    - Repository는 Mock으로 구성한다.
- **실행:** `create(request)` 호출
- **기대 결과:**
    - `INVALID_TRANSACTION_ACCOUNT`에 해당하는
      `GrimaultException`이 발생한다.
    - `TransactionRepository.save()`는 호출되지 않는다.
- **테스트 형태:** `@ParameterizedTest`

#### 입력 조건

| 원계정 시작일 | 목적계정 시작일 | 거래일 | 기대 결과 |
|---|---|---|---|
| 2026-02-01 | 2026-01-01 | 2026-01-31 | 원계정 시작일 위반으로 거부 |
| 2026-01-01 | 2026-02-01 | 2026-01-31 | 목적계정 시작일 위반으로 거부 |
